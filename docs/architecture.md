# Architecture and module contracts

This repository turns the discussion pack **Public Voice Between Elections** (v0.1, 13 October
2026) into three things: structured open data, an accessible static website, and a
synthetic case-workflow prototype. This document is the contract every module follows.

## Principles, each traceable to the pack

1. **Proposal, not platform.** Every generated page carries the pack's disclaimer. Nothing we
   write may upgrade a *proposed* commitment into an *existing* legal guarantee. When in doubt,
   quote the pack rather than paraphrase it.
2. **Zero dependencies.** `git clone` plus Node 22 is enough to validate, test, build and run.
   No `npm install`. This keeps the code auditable and usable on slow connections.
3. **Data first.** `data/*.json` is the source of truth for structured content;
   `content/pack/*.md` is the source of truth for prose. Both are produced by
   `tools/import-pack.py` from the exported Google Doc in `content/source/`. Never hand-edit
   generated output; fix the importer or the source document.
4. **Works without JavaScript.** The site is complete static HTML. JavaScript only enhances
   (filtering, search). Pages must stay usable at 320px width, in print, and with a screen reader.
5. **Synthetic only.** The workflow engine refuses any record that is not marked synthetic and
   rejects personal-data patterns. The pack says: test with synthetic records before handling
   sensitive complaints; collect only necessary personal information.
6. **Human validation, no invented enforcement.** Owner suggestions are advisory and need a human
   validation marker. The engine records, reminds and escalates review. It never invents a fine,
   removal, court order or mandatory hearing.
7. **Preserve, don't erase.** Challenges, dissent, transfers and overdue states are recorded, never
   overwritten. A referral or transfer is not a resolution.

## Repository layout

```
content/source/      exported Google Doc (provenance; do not edit)
content/pack/        sections 1–9 as markdown with frontmatter (generated by importer)
data/                structured JSON (generated by importer)
schema/              JSON Schema (draft 2020-12) describing data/ for interop
tools/               import-pack.py (Python 3.11+, stdlib only)
scripts/             validate.mjs, export-csv.mjs, build-site.mjs, serve.mjs
src/workflow/        case-workflow engine (pure functions) + scenarios/
src/site/            site generator modules (markdown, html, pages)
src/cli.mjs          command-line entry: simulate, issue, routes, org
assets/              styles.css, enhance.js (copied into site/assets/)
i18n/                UI strings: en.json complete; hi.json, mr.json draft
tests/               node:test suites (*.test.mjs)
docs/                project docs in doc-flow format (frontmatter, kebab-case)
.github/             issue forms, PR template, CI, Pages deploy
site/                generated output (gitignored)
```

## Conventions

- ES modules, `.mjs` extension, JSDoc type annotations, `"use strict"` implied.
- Tests use `node:test` and `node:assert/strict`; run with `node --test tests/`.
- No third-party packages at runtime or in tests. `npm run typecheck` is optional and uses `npx`.
- Dates are ISO 8601 `YYYY-MM-DD` strings in data and APIs; computations use UTC.
- Use the pack's vocabulary: *issue family*, *challenge route*, *lead office*, *co-owner*,
  *reasoned response*, *verified transfer*, *preserved dissent*, *evidence of change*.
- Scripts exit non-zero on failure and print every problem, not only the first.
- Relative links only in generated HTML, so the site works at any base path (GitHub Pages
  project path, local file, artifact preview).

## Data model (`data/`)

| File | Shape |
|------|-------|
| `pack.json` | title, subtitle, tagline, version, date, disclaimer, workingContext, aiAssistedNotice, sourceDocument, counts |
| `issues.json` | array of 100: `id` ("001"–"100"), `slug`, `title`, `domainId`, `raise[]`, `answer[]`, `possibleChange`, `evidence[]`, `challengeRoutes[]` (codes) |
| `domains.json` | array of 10: `id` ("d01"–"d10"), `slug`, `name`, `range` [from,to], `issueIds[]` |
| `routes.json` | `items[]` of 7: `code` (A I R H J P V), `name`, `slug`, `description`; `caveat` |
| `organisations.json` | `selectionBasis`, `items[]` of 13: `id`, `number`, `name`, `slug`, `documentedRelevance`, `agendaLinksText`, `agendaIssueIds[]`, `suggestedRemoteContribution`, `status`, `officialEvidenceUrl`, `publicRouteUrl`; `additionalNetworkLead` |
| `commitments.json` | `items[]` of 7: `id`, `name`, `description`; `caveat` |
| `participation-routes.json` | `items[]` of 3: `id` (individual-remedy, systemic-review, policy-or-law), `name`, `text`, `example`, `expectedResult`, `note`; `caveat` |
| `refusal-responses.json` | `items[]` of 7: `id`, `situation`, `response`; `caveat` |
| `contribution-types.json` | `items[]` of 8: `id`, `name`, `description`; `form.fields[]`, `form.caveat` |
| `sources.json` | `intro`, `items[]` of 8: `number`, `title`, `url` |
| `process-targets.json` | `sourceText`, `caveat`, `targets[]`: `id`, `stage`, `description`, `days`, `dayType` (calendar/working), `from` (received/admitted), optional `appliesTo[]`, `overridableByLaw`; `existingLawReference` |

Route codes: A Administrative review · I Information / RTI · R Regulator or specialist redress ·
H Rights or protection route · J Qualified legal review / competent court or tribunal ·
P Policy hearing / legislative scrutiny / lawful advocacy · V Vigilance or audit referral.

## Module 1: validator, schemas, CSV export

- `scripts/validate.mjs` loads every file in `data/` and `content/pack/` and checks:
  issue ids are exactly "001"…"100" in order, slugs unique, every `domainId` exists and the id
  falls inside the domain's range, `challengeRoutes` non-empty with valid unique codes,
  organisation `agendaIssueIds` resolve and match `agendaLinksText`, every URL is `https://`
  and parses, route codes are exactly the seven, process-target ids unique and `from`/`dayType`
  enums valid, `pack.counts` match actual counts, nine pack sections with frontmatter
  `section: 1..9`. Prints all errors as `file: path: message`; exit 1 if any.
- `schema/*.schema.json`: one JSON Schema (draft 2020-12) per data file, with `$id`,
  `title`, `description`, `additionalProperties: false` where safe. The validator also
  checks data against these schemas with a small built-in checker (type, required, enum,
  pattern, items, minItems, additionalProperties). No ajv.
- `scripts/export-csv.mjs` writes `exports/issues.csv`, `exports/organisations.csv`,
  `exports/organisation-issue-links.csv` (RFC 4180 quoting, UTF-8 with no BOM).
- Tests: `tests/data.test.mjs` (data invariants, schema checker unit tests with a deliberately
  broken fixture, CSV round-trip).

## Module 2: workflow engine (`src/workflow/`)

Pure functions over plain objects. Every mutation returns a new case object with an appended
event; the input is never modified. Export from `src/workflow/index.mjs`.

**Case shape**

```js
{
  id: 'SYN-0001',                 // must start with 'SYN-'
  synthetic: true,                // required; anything else throws SyntheticOnlyError
  participationRoute: 'individual-remedy' | 'systemic-review' | 'policy-or-law',
  issueId: '077',                 // must exist in data/issues.json
  channel: 'assisted' | 'offline' | 'telephone' | 'postal' | 'digital',
  receivedAt: 'YYYY-MM-DD',
  summary: 'short synthetic description (checked for personal-data patterns)',
  consent: { attribution: 'anonymous' | 'organisation' | 'named' },
  legalDeadlineDays: number | null,   // governing law override for the response target
  calendar: { weekendDays: [0, 6], holidays: [] },
  state: 'received' | 'routed' | 'responded' | 'admission-pending' | 'admitted' | 'declined'
       | 'hearing-scheduled' | 'heard' | 'decided' | 'closed',
  owner: null | { leadOffice, coOwners: [], applicableRules: [], validatedBy: 'human', responseDueAt },
  responses: [],   // reasoned responses, each with assessment { boilerplate, missing[] }
  changes: [],     // ledger entries kind: 'promised' | 'completed' | 'verified'
  challenges: [],  // preserved challenges to closures/refusals
  dissent: [],     // preserved dissent from hearings
  transfers: [],   // verified transfers (never a closure)
  referrals: [],   // protected / vigilance / emergency referrals
  flags: { protected: false, urgent: false },
  closure: null | { at, reason },
  events: [ { at, type, actorRole, data } ]
}
```

`actorRole` is one of filer, assistant, intake, lead-office, supervisor, reviewer, hearing-panel,
verifier, system. No personal identities anywhere.

**API** (all take `(kase, params)` and return a new case unless noted)

- `createCase(params)` — validates shape, `assertSynthetic`, `rejectPersonalData`, issueId exists.
- `issueReceipt(kase, { at })` — records receipt; digital receipts are due same day, others
  within two working days (from `process-targets.json`).
- `suggestOwner(issueId)` → `{ indicative: issue.answer, requiresHumanValidation: true, note }`.
  Advisory only.
- `routeCase(kase, { at, leadOffice, coOwners, applicableRules, validatedBy })` — throws
  `HumanValidationRequiredError` unless `validatedBy === 'human'`; sets `owner.responseDueAt`
  from the 21-day target or `legalDeadlineDays`.
- `respond(kase, { at, decision: 'action' | 'refusal' | 'interim', evidence, jurisdiction,
  reasons, challengeRoutes })` — appends a response with `assessResponse()` result.
- `assessResponse(response)` → `{ boilerplate: boolean, missing: string[] }`. Boilerplate when
  reasons are empty or generic (fewer than 12 words, or match a small list of stock phrases such
  as "disposed", "noted", "forwarded for necessary action" with nothing else), or evidence,
  jurisdiction or challengeRoutes are missing.
- `transfer(kase, { at, toOffice, verified, acknowledgedAt })` — throws unless `verified === true`
  and `acknowledgedAt` present; records transfer; state unchanged; never closes.
- `challengeClosure(kase, { at, grounds })` — preserves the challenge, reopens if closed,
  records event `case-specific-reasons-requested`.
- `recordChange(kase, { at, kind, description, verifier })` — `verified` requires a `verifier`
  role that is independent (`verifier` or `reviewer`), otherwise throws.
- Systemic path: `requestAdmission`, `decideAdmission(kase, { at, admitted, reasons })`,
  `scheduleHearing(kase, { at, hearingAt })`, `recordHearing(kase, { at, evidence,
  counterarguments, agreement, dissent })` (dissent preserved into `kase.dissent`),
  `decide(kase, { at, decision, reasons })`.
- `markProtected(kase, { at, reason: 'retaliation' | 'credible-harm' })` — sets
  `flags.protected`, records a protected referral; the case disappears from public summaries.
- `referToVigilance(kase, { at, body })` — records referral with the note
  "Allegations are not findings of guilt."
- `flagUrgent(kase, { at })` — records the emergency-services notice; the engine is not a
  responder.
- `close(kase, { at, reason: 'action-completed' | 'refused-with-reasons' | 'withdrawn-by-filer'
  | 'duplicate' })` — throws if there is no response, if the latest response is boilerplate, or
  if `reason` is anything like transfer/referral.
- `deadlines(kase)` → due dates per stage derived from `data/process-targets.json`.
- `status(kase, { now })` → `{ state, overdue: [{ stage, dueAt, daysOverdue }], nextActions }`.
- `onSilence(kase, { now })` — if any stage is overdue and no response exists, appends
  `supervisor-notified` and `review-enabled` events with `filingTimePreserved: true`.
- `toPublicSummary(kase, { now })` → `null` when protected; otherwise only `issueId`,
  `participationRoute`, `state`, `overdueStages`, `changeCounts`, `hasPreservedChallenge`.
  Never free text, never ids that could be traced.
- `guards.mjs`: `assertSynthetic`, `rejectPersonalData(obj)` (throws `PersonalDataError` on keys
  such as name, phone, mobile, email, aadhaar, aadhar, uid, address, dob, dateOfBirth, voterId,
  epic, pan, or on values matching a 12-digit number, a 10-digit number starting 6–9, or an
  email address).
- `calendar.mjs`: `addCalendarDays`, `addWorkingDays(date, n, { weekendDays, holidays })`,
  `daysBetween`.
- `scenarios/`: one file per scenario exporting `{ id, title, run() }`: `ration-denial`
  (individual remedy), `authentication-failures` (systemic), `portable-voting` (policy),
  `silence`, `wrong-office`, `boilerplate-closure`, `retaliation`, `alleged-corruption`.
- `src/cli.mjs`: `simulate <scenario>|all`, `list`, `issue <id>`, `routes`, `org <number>`.
  Prints a timeline table to stdout. No colours required.

Tests: `tests/workflow.test.mjs`, `tests/guards.test.mjs`, `tests/calendar.test.mjs`,
`tests/scenarios.test.mjs` (every scenario runs and ends in a consistent state).

## Module 3: site generator (`scripts/build-site.mjs`, `src/site/`, `assets/`, `i18n/`)

Output in `site/`. Pages (all with the shared layout: skip link, header nav, disclaimer banner,
main, footer with licence, version and source link):

- `index.html` — why, the four questions, commitments, three routes, calls to action.
- `issues/index.html` — all 100 grouped by domain, with a no-JS-safe filter form (domain,
  route, text) enhanced by `assets/enhance.js`.
- `issues/<id>.html` ×100 — full card, route meanings, organisations whose agenda links
  include the issue, previous/next links, link to the issue-brief template.
- `domains/<slug>.html` ×10.
- `routes.html` — Appendix B with the caveat.
- `organisations.html` — 13 cards; status text verbatim; both links; agenda links as links.
- `process.html` — sections 3, 4, 5: participation routes, existing foundations, process
  targets table, refusal responses.
- `contribute.html` — section 6 types, the contribution form fields, link to GitHub issue
  forms, section 8 invitation as a copyable block.
- `organising-cycle.html` — section 9.
- `sources.html` — Appendix C.
- `about.html` — provenance, versions, licences, AI-assisted notice, how to re-import.
- `print/pack.html` — the whole pack on one printable page.
- `data/*.json` copies, `search-index.json` (id, title, domain, routes, text snippet).
- `sitemap.xml`, `robots.txt`, `404.html`.

Rules: semantic HTML5, one `h1` per page, heading levels never skip, `lang` attribute,
`<title>` of the form `Page name · Public Voice Between Elections`, every link has text, tables
have `<th scope>`, colour contrast at least 4.5:1, visible focus, `prefers-reduced-motion`
respected, print stylesheet, no external requests (no fonts, no CDNs). System font stack.
Escape all interpolated text. Markdown converter in `src/site/markdown.mjs` supports headings,
paragraphs, bullet lists, links `[text](url)` and `<url>`, bold, italics; nothing else.

i18n: `i18n/en.json` holds all UI strings. `hi.json` and `mr.json` hold draft translations of
the same keys with `"_status": "draft-unreviewed"`. `build-site.mjs --lang hi` writes
`site/hi/` with translated chrome and English content plus a visible notice that content
translation is pending. Default build is English only.

Tests: `tests/site.test.mjs` builds into a temporary directory and asserts: 100 issue pages, 10
domain pages, each page has `<html lang`, exactly one `<h1>`, a `<main>`, a skip link, a
`<title>`, no empty `<a>`, and every internal href resolves to a generated file.
