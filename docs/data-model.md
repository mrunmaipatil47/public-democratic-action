# Data model

Everything under `data/` is generated by `tools/import-pack.py` from the exported pack in
`content/source/`. Do not edit these files by hand; see [[how-to-reimport-the-pack]]. Each file has a
JSON Schema (draft 2020-12) in `schema/<name>.schema.json`, and `npm run validate` checks the data
against it.

All text fields hold the pack's words. Where the pack hedges, the data hedges. Nothing here is a
legal guarantee.

## pack.json

Front matter of the document and the counts the validator checks against.

| Field | Meaning |
|-------|---------|
| `title`, `subtitle`, `tagline` | The first three lines of the pack. |
| `version` | `v0.1`. |
| `dateText`, `date` | "13 October 2026" and `2026-10-13`. |
| `purpose` | "Prepared for discussion, correction and possible collaboration". |
| `disclaimer` | The proposal-not-platform sentence. Every generated page shows it. |
| `workingContext` | The pack's closing working-context note. |
| `aiAssistedNotice` | The pack's AI-assisted preparation notice. |
| `sourceDocument` | URL of the Google Doc. |
| `counts` | `issues`, `domains`, `routes`, `organisations`, `sources`. Must match the other files. |
| `appendices` | `A`, `B`, `C`, each with the appendix `title` as the pack gives it; `A` also carries `intro`, the Appendix A paragraph with the caveat that owners are indicative and that no listed evidence is asserted to have been collected. |

## issues.json

One card per issue family, in Appendix A order. The pack's words: each card names examples of who
can raise it, an indicative owner, possible lawful changes, evidence to collect and conditional
refusal routes. Owners require current state/sector validation. No evidence listed is asserted to
have already been collected.

| Field | Type | Meaning |
|-------|------|---------|
| `id` | string `"001"`–`"100"` | Stable reference. Zero-padded, three digits. |
| `slug` | string | URL-safe form of the title. Unique. |
| `title` | string | The card's title. |
| `domainId` | string `"d01"`–`"d10"` | The domain whose range contains the id. |
| `raise[]` | string[] | Who can raise it (the card's "Raise"). |
| `answer[]` | string[] | Indicative owner(s) (the card's "Answer"). Advisory until a human validates. |
| `possibleChange` | string | Possible lawful changes. |
| `evidence[]` | string[] | Evidence to collect. |
| `challengeRoutes[]` | route codes | Conditional refusal routes. Non-empty, unique, in the card's order. |

## domains.json

Ten groups of ten, from the Appendix A headings.

| Field | Meaning |
|-------|---------|
| `id` | `"d01"`–`"d10"`. |
| `slug`, `name` | From the heading, for example "Democracy, public voice and media". |
| `range` | `[from, to]` issue ids, for example `["001", "010"]`. |
| `issueIds[]` | The ten ids in the range. |

## routes.json

Appendix B. The seven challenge routes and the caveat that they are options, not a compulsory
ladder, and that urgent protection and individual relief must not wait for a public hearing.

| Field | Meaning |
|-------|---------|
| `items[].code` | One of the seven codes below. |
| `items[].name`, `items[].slug` | Route name and URL-safe form. |
| `items[].description` | The route's meaning and its limits, in the pack's words. |
| `caveat` | The closing sentence of Appendix B. |

### Route codes

| Code | Route | What the pack says it is not |
|------|-------|-------------------------------|
| A | Administrative review | Check exclusions and deadlines. |
| I | Information / RTI | Information access does not itself enforce a remedy. |
| R | Regulator or specialist redress | Only within its remit and after applicable prerequisites. |
| H | Rights or protection route | A recommendation is not necessarily a binding executable order. |
| J | Qualified legal review / competent court or tribunal | No guaranteed admission, relief or timing. |
| P | Policy hearing / legislative scrutiny / lawful advocacy | Automatic hearings require institutional adoption. |
| V | Vigilance or audit referral | A referral is not a finding of guilt or a guarantee of compensation. |

## organisations.json

Section 7. Thirteen organisations, selected on publicly documented relevant work and a plausible
contribution. Willingness, capacity, affiliation and remote arrangements remain unconfirmed for
every entry. No personal contacts.

| Field | Meaning |
|-------|---------|
| `selectionBasis` | The section's opening paragraph. |
| `items[].id`, `number` | `"org-01"`–`"org-13"` and the integer. |
| `items[].name`, `slug` | Organisation name and URL-safe form. |
| `items[].documentedRelevance` | What its public pages show. |
| `items[].agendaLinksText` | The ranges as written, for example `"004–008, 037, 067, 088"`. |
| `items[].agendaIssueIds[]` | The same, expanded to ids. The validator checks they match. |
| `items[].suggestedRemoteContribution` | Our suggested request, not an advertised opening. |
| `items[].status` | What is verified and what is not. Rendered verbatim. |
| `items[].officialEvidenceUrl` | An `https://` page on the organisation's own site. |
| `items[].publicRouteUrl` | The pack's "Public institutional route" for the organisation (often its home page). Not evidence of a volunteer opening; see `status`. |
| `additionalNetworkLead` | The closing note about possible referral routes. |

## process-targets.json

Section 4's suggested process targets, structured. The pack's sentence is kept in `sourceText`
and the importer refuses to run if it changes, so the structured targets cannot drift from it
unnoticed.

| Field | Meaning |
|-------|---------|
| `sourceText` | The full sentence from the pack. |
| `caveat` | These are design targets. Applicable law and urgent safety procedures take precedence. |
| `targets[].id` | `receipt-digital`, `receipt-assisted`, `routing`, `ordinary-response`, `systemic-admission`, `systemic-hearing`, `systemic-decision`. |
| `targets[].stage` | `receipt`, `routing`, `response`, `admission`, `hearing`, `decision`. |
| `targets[].days`, `dayType` | Number of days and `calendar` or `working`. |
| `targets[].from` | Counted from `received` or from `admitted`. |
| `targets[].appliesTo[]` | Optional. Channels (`digital`, `assisted`, …) or participation routes (`systemic-review`). Absent means every case. |
| `targets[].overridableByLaw` | Optional. True for the 21-day ordinary response: governing law may specify otherwise. |
| `existingLawReference` | The DARPG 21-day and RTI 30-day / 48-hour sentence from the pack, with the numbers broken out and a note that they are quoted, not asserted as guarantees. |

## search-index.json (generated by the site build, not in `data/`)

`npm run build` writes `search-index.json` beside each language root (`site/search-index.json`,
`site/hi/search-index.json`, …) as a flat, reusable index of the issue cards for other tools. The
site's own filter does not fetch it; `assets/enhance.js` works from data attributes on the issue
list, so the pages stay complete without JavaScript. It is derived from `issues.json` and
`domains.json` and has no schema of its own. One entry per issue card: `id`, `title`, `domain` (name), `domainId`, `routes[]` (codes),
`url` (`issues/<id>.html`, relative to the language root) and `text` (the card's raise, answer,
possible change and evidence lines joined into one string). Every copy holds the English content,
since content translation is a later step; see [[how-to-add-a-language]].

## Ids are stable references

The pack says: issue numbers are stable references. Local groups should correct, split, merge or add
issues based on evidence. So:

- An issue id never changes meaning. How a split or merge is represented in `issues.json` (new ids
  beyond 100, a `supersededBy` field, or something else) is to be confirmed with the pack's authors.
  The current validator requires exactly `001`–`100` in ten domains of ten, and the data has no
  field for a redirected id, so today a split or merge is a change to the source document followed
  by a new import.
- Domain ids follow the ranges (`d08` is always `071`–`080`).
- Organisation ids follow the pack's numbering (`org-04` is always SNS).
- Route codes are the seven letters and nothing else.
- The workflow engine checks `issueId` against `issues.json` and refuses unknown ids.

## How to cite an issue

Write "Issue 077" in prose, with the three-digit id. Add the title on first mention: "Issue 077,
Ration access and food-security exclusions". In data and URLs use the id (`077`) or slug
(`ration-access-and-food-security-exclusions`). Cite the pack as "Public Voice Between Elections,
draft v0.1, 13 October 2026".
