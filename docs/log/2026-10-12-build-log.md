# Build log, 12 October 2026

First build day. The pack (draft v0.1, dated 13 October 2026) was imported and the repository went
from empty to a working skeleton with four modules in flight. Work was done with AI assistance, in
parallel, on one branch.

## What was built

**Import.** `tools/import-pack.py` parses the Google Doc markdown export into eleven JSON files and
nine pack sections. It round-trips every issue card against the source and refuses to run if the
structure or the process-targets sentence changes. Output: 100 issues, 10 domains, 7 routes, 13
organisations, 8 sources, 7 process targets, 9 sections.

**Data.** `data/*.json` and `content/pack/*.md`, generated. `schema/*.schema.json`, one per data
file. `exports/*.csv` from `npm run export:csv`.

**Skeleton.** `package.json` with scripts and no dependencies; `.editorconfig`, `.gitignore`,
`tsconfig.json` for optional typechecking; MIT and CC BY-SA 4.0 licences; `README.md`;
`docs/architecture.md` as the binding module contract.

**Module 1, validator and schemas.** `scripts/validate.mjs` checks ids, slugs, ranges, route codes,
agenda links, URLs, counts, pack sections and schema conformance, and prints every problem.
`scripts/export-csv.mjs`. Tests in `tests/data.test.mjs`.

**Module 2, workflow engine.** `src/workflow/` with pure functions, guards, calendar, deadlines,
public summary and eight scenarios. `src/cli.mjs` for `simulate`, `list`, `issue`, `routes`, `org`.
Tests for the engine, guards, calendar and scenarios. 222 tests passing at the end of the day.

**Module 3, site generator.** `scripts/build-site.mjs`, `src/site/`, `assets/`, `i18n/`. In progress
at the time of writing; the contract is in `docs/architecture.md`.

**Module 4, documentation and templates.** `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`,
seven issue forms and `config.yml`, the pull request template, `ci.yml` and `pages.yml`, and the
docs: decision log, data model, workflow engine, two SOPs, issue brief template, invitation letter,
glossary, this log.

## Decisions

Recorded in full in [[decision-log]]. In one line each: zero dependencies; generated data, not
hand-edited; static site without a framework; synthetic-only engine; human validation for routing;
relative links only; MIT for code and CC BY-SA 4.0 for content; `node:test`; English first with
draft Hindi and Marathi UI strings.

Also decided today, smaller: docs use kebab-case filenames and YAML frontmatter with `title`,
`type`, `project`, `tags`, `source`, `created`, `updated`, `status`, and end with a "Related" section
of wikilinks. Every issue form carries the same required privacy checkbox. CI re-runs the importer
and diffs against the committed data.

## Open questions

1. **Default branch and pull request.** `pages.yml` deploys on pushes to `main`. The work is on a
   feature branch. Confirm that `main` is the default branch, enable Pages with source "GitHub
   Actions", and open the PR. Until then the deploy workflow does nothing.
2. **`npm test` script.** `node --test tests/` fails on Node 22.22 ("Cannot find module …/tests")
   because a bare directory is not a test pattern. Change the script to `node --test` or
   `node --test 'tests/*.test.mjs'`. CI calls `npm test`, so CI is red until this is fixed.
3. **Licence choice to confirm.** MIT plus CC BY-SA 4.0 is in place. The repository owner should
   confirm before the first public release, in particular ShareAlike for data.
4. **Hindi and Marathi strings need review.** `i18n/hi.json` and `i18n/mr.json` are planned as
   `draft-unreviewed` and were not yet in the tree at the end of the day. When they land, a meaning
   check with users is needed before the status changes. See [[how-to-add-a-language]].
5. **Owner validation for each state.** Every issue card's "Answer" is indicative. The pack says
   owners require current state/sector validation. Nobody has validated an owner for any state yet.
   This is the first job for the law-and-jurisdiction contribution type, one issue at a time.
6. **Contact links in the issue chooser.** `config.yml` links to the README and `SECURITY.md`. Add a
   Discussions link once Discussions are enabled on the repository.
7. **Private vulnerability reporting.** `SECURITY.md` prefers GitHub's private reporting. Enable it
   in repository settings, or the fallback (an issue asking for a private channel) is the only route.
8. **Content translation pipeline.** Where translated issue briefs live and how the generator picks
   them up is not designed yet. UI strings only for now.
9. **Importer date.** `pack.json`'s `date` is hard-coded to `2026-10-13` in the importer. Fine for
   v0.1; must change with the next version.

## Addendum, 13 October 2026: review fixes

A review of Module 4 found the following; each fix has a check in `tests/docs.test.mjs`.

- `ci.yml` and `pages.yml` run `node --test 'tests/*.test.mjs'` directly instead of `npm test`, so
  the site artifact and the Pages deploy no longer depend on the broken `package.json` script.
  Open question 2 still stands for `npm test` run locally.
- The CI `reimport` job reads the source filename from `package.json`'s `import` script instead of
  hard-coding v0.1, and the re-import SOP's version-bump grep covers `.github/`.
- An eighth form, `private-channel.yml`, makes the no-details fallback route in `SECURITY.md` and
  `CODE_OF_CONDUCT.md` usable while blank issues stay disabled. `config.yml` links `SECURITY.md`
  through `blob/HEAD/`, not `blob/main/`, because no `main` branch exists yet.
- Every contribution form carries the section 6 fields that were missing (effort and availability,
  privacy needs, reviewer, expected output, all optional; method on `correction` and
  `legal-route-map`) and the credit dropdown (added to `organisation-suggestion` and
  `synthetic-case`), so the claim in `CONTRIBUTING.md` that every form maps onto the pack's form is
  true.
- [[workflow-engine]]: the `respond` row and the `responded` state text now match
  `src/workflow/case.mjs` (an interim response moves `routed` to `responded`; a response from the
  systemic states leaves the state unchanged); `routeCase` also accepts `routed`; `onSilence` is in
  the transitions table because it appends events.
- [[how-to-add-a-language]]: `i18n/hi.json` and `i18n/mr.json` are in the tree as
  `draft-unreviewed` (open question 4 and the build check above were stale when written); the build
  step builds English too; codes are BCP 47; `i18n/README.md` is the file-format reference.
- [[data-model]] no longer describes retiring an id on merge, which the validator forbids.
  `CONTRIBUTING.md` puts scenario code under MIT and scenario storylines under CC BY-SA.

## Addendum, 13 October 2026: second review pass

- Open question 2 is closed. `package.json`'s test script is `node --test`, `npm test` passes, and

- [[architecture]] matches the tree again: `dateText` and `purpose` on `pack.json`, `print.css`,
