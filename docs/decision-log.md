# Decision log

One entry per decision. Context, decision, consequences, status. Newest at the bottom. A decision is
reversed by a new entry, not by editing the old one.

## 2026-10-12 — Zero dependencies

**Context.** The repository must be auditable by people who are not developers, usable on slow
connections, and runnable years from now. Every dependency is a trust decision and a download.

**Decision.** No runtime or dev dependencies. `git clone` plus Node 22 is enough to validate, test,
build and run. No `npm install`. The importer uses the Python standard library only.

**Consequences.** We write our own small markdown converter, JSON Schema checker, CSV writer and
static server. Each is a few hundred lines and does less than the library it replaces. The optional
`npm run typecheck` uses `npx` and is the one exception, because it is not needed to run anything.

**Status.** Adopted.

## 2026-10-12 — Generated data, not hand-edited data

**Context.** The pack is a Google Doc owned by its authors. New versions will come. If `data/*.json`
and `content/pack/*.md` were edited by hand, the next import would overwrite the edits, or the
data would drift from the document.

**Decision.** `tools/import-pack.py` is the only writer of `data/` and `content/pack/`. Corrections
go to the source document through a correction issue, then re-import. CI re-runs the importer and
fails if the committed output differs.

**Consequences.** Fixing a typo means fixing the document, which is where the typo lives anyway.
The importer fails loudly if the document structure changes, so a new version cannot be imported
silently wrong. The process-targets sentence is pinned: if it changes, someone must update the
structured targets by hand and the importer says so.

**Status.** Adopted.

## 2026-10-12 — Static site without a framework

**Context.** Pages must work without JavaScript, at 320px, in print and with a screen reader. The
site is read far more than it is built.

**Decision.** Plain HTML generated by `scripts/build-site.mjs` from the data and pack sections.
JavaScript only enhances (filtering, search). No framework, no bundler, no CDN, no web fonts.

**Consequences.** Every page is a complete document. The filter form on the issues index works as a
plain form. Tests assert one `h1`, a skip link, a `<main>` and resolvable links on every page.

**Status.** Adopted.

## 2026-10-12 — Synthetic-only workflow engine

**Context.** Section 9 of the pack: test the process with synthetic records before handling
sensitive complaints. Section 2: collect only necessary personal information. A prototype that
accepts real cases becomes a liability the moment it is cloned.

**Decision.** The engine throws unless `synthetic: true` and the id starts with `SYN-`. It rejects
personal-data patterns in keys and values. Scenarios invent wards, offices and records and say so.

**Consequences.** Nobody can test the engine on a real complaint without changing the code. The
public summary carries no free text and no traceable ids. A protected case is not published at all.

**Status.** Adopted.

## 2026-10-12 — Human validation for routing

**Context.** Appendix A: owners require current state/sector validation. Section 2: every case has
a verified lead office. An automatic router would turn an indicative owner into an asserted one.

**Decision.** `suggestOwner()` returns the card's indicative owner with
`requiresHumanValidation: true`. `routeCase()` throws unless `validatedBy === 'human'`. The engine
records, reminds and escalates review. It never invents a fine, removal, court order or mandatory
hearing.

**Consequences.** Routing always has a human in the record. The engine cannot be read as claiming
jurisdiction. Automation is limited to deadlines, overdue status and preservation of challenges.

**Status.** Adopted.

## 2026-10-12 — Relative links only

**Context.** The site will be served from a GitHub Pages project path, opened from a local file,
and previewed as an artifact. Each has a different base URL.

**Decision.** Generated HTML uses relative links only. No `<base>`, no absolute paths.

**Consequences.** The site works wherever it is copied. Tests check that every internal href
resolves to a generated file. The sitemap is the one place an absolute URL is needed and it is
configured, not hard-coded.

**Status.** Adopted.

## 2026-10-12 — MIT for code, CC BY-SA 4.0 for content and data

**Context.** Code and content have different audiences. Civic groups will adapt the text; developers
will reuse the scripts. The pack's authors want corrections to flow back.

**Decision.** Code under MIT (`LICENSE`). Content, data, docs, i18n strings and rendered text under
CC BY-SA 4.0 (`LICENSE-CONTENT.md`). Contributions are accepted under the same split.

**Consequences.** Adapted packs must stay open and credit the source. Organisation names are not
licensed; the licence covers our descriptions of their public work. The choice is to be confirmed
with the repository owner before the first public release.

**Status.** Adopted, licence choice to be confirmed.

## 2026-10-12 — node:test for all tests

**Context.** Zero dependencies rules out jest, vitest and mocha. Node 22 ships a test runner.

**Decision.** `node:test` and `node:assert/strict` only. Suites live in `tests/*.test.mjs`.

**Consequences.** No watch mode, no snapshot plugins. Tests are plain functions and run in about a
second. Note: Node 22 does not accept a bare directory as a test pattern, so the test script should
use `node --test 'tests/*.test.mjs'` or plain `node --test`.

**Status.** Adopted.

## 2026-10-12 — English first, with draft Hindi and Marathi UI strings

**Context.** Section 6 asks for translation of issue briefs into Marathi, Hindi or another relevant
language, with meaning checked with users. We have no checked translations yet. Shipping unchecked
text as if it were checked would be worse than shipping English.

**Decision.** `i18n/en.json` is complete and is the default build. `hi.json` and `mr.json` hold
draft translations of the UI chrome only, marked `"_status": "draft-unreviewed"`. A `--lang` build
shows translated chrome, English content, and a visible notice that content translation is pending.

**Consequences.** Translators have a fixed key set to work from. Nothing claims to be reviewed until
it is. Content translation is a later, separate step. See [[how-to-add-a-language]].

**Status.** Adopted, hi/mr strings need review.
